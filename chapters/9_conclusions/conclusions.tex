\section{Conclusions}
\label{ch:conclusions}

Architectural static analysis and dependency extraction represent fundamental
pillars of modern software engineering, underpinning critical activities
ranging from architectural smell detection and refactoring recommendation to
modularity assessment and technical debt monitoring. However, the growing
prevalence of multi-language software systems has highlighted a fundamental
limitation in traditional static analysis tools: their reliance on
language-specific compiler frontends and dedicated analysis pipelines.
Traditionally, supporting multiple programming languages requires engineering a
separate extraction and resolution pipeline for each ecosystem, integrating
distinct compiler frontends, custom parsers, and language-specific symbol
resolvers. This fragmentation introduces substantial engineering complexity,
duplicates core analysis logic across languages, and increases the effort
required to develop and maintain multi-language tooling.

To address these limitations, this work designed, formalized, and
empirically validated \textbf{OmniDeps}, a high-performance, language-agnostic
static analysis framework that decouples architectural dependency extraction
from native compiler toolchains. Operating under the foundational premise
that the analyzed source code compiles successfully within its native build
environment, OmniDeps shows that Concrete Syntax Trees (CSTs) can be
directly queried and projected into normalized architectural dependency graphs
without executing compiler type-checking passes or whole-program bytecode
verification.

This research delivered three primary contributions:
\begin{enumerate}
  \item \textbf{Intermediate Representation and Extraction Heuristics}:
    We established a strongly typed, mathematically grounded Intermediate
    Representation based on algebraic data types, designed
    to abstract modules, structured types, functions, and imports away from
    idiosyncratic language grammars. This representation is paired with a
    configurable, heuristic-driven extraction mechanism that projects
    heterogeneous Concrete Syntax Trees (CSTs) generated by Tree-sitter across
    different languages into a uniform structural model.
  \item \textbf{Multi-Language Resolution Pipeline}:
    We designed and formalized a unified analysis pipeline in native Rust,
    achieving uniform dependency extraction across five diverse programming
    languages: C, C++, Java, Python, and Rust. To perform language-independent
    name resolution within this pipeline, we formulated an algebraic query
    language governed by three orthogonal primitives (\texttt{Find},
    \texttt{Extract}, and \texttt{Call}) to model lexical lookups, member
    traversals, and behavioral invocations over a hierarchical Scope Tree.
  \item \textbf{Rigorous Empirical Validation and Graph Harmonization}:
    To overcome the fundamental challenge of comparing heterogeneous static
    analyzers, we formulated a Graph Harmonization Framework based on
    canonical entity identification, semantic entity lifting,
    intermediate package synthesis, and unified edge taxonomies. Using this
    framework, OmniDeps was validated against synthetic benchmark oracles
    and benchmarked against three established analyzers (\textit{Arcan},
    \textit{Depends}, and \textit{Entangle}) across a dataset of \textbf{156
    open-source repositories} comprising nearly 98 million lines of code.
\end{enumerate}

The empirical evaluation confirmed the effectiveness and practical viability of
the proposed approach. On controlled synthetic benchmarks, OmniDeps consistently
recovered the expected structural entities and relationships across all five
supported languages, validating both the extraction heuristics and the query
resolution engine. When evaluated on large-scale open-source repositories, the
framework demonstrated strong structural alignment with established analyzers in
explicitly typed, object-oriented ecosystems, showing that syntax-directed
extraction can closely approximate compiler-backed symbol tables for
architectural modeling. At the same time, the cross-language analysis clarified
the intrinsic boundaries of purely syntactic static analysis: in dynamically
typed languages, entity and hierarchy identification remains accurate while
behavioral call resolution is naturally bounded by the absence of runtime type
information; in procedural systems, preprocessor macro masking and header
inlining introduce an inherent trade-off between type visibility and declaration
duplication across compilation units. Finally, by operating directly on source
files without requiring build configuration or compilation, OmniDeps achieved
high operational reliability across the benchmark corpus and scaled linearly
with codebase size, completing analysis in a fraction of the time required by
traditional tools.

In conclusion, this work proves that language-agnostic architectural dependency
extraction is both theoretically sound and industrially viable. By trading
redundant compiler-level type verification for declarative CST pattern queries
and decoupled lexical scope trees, OmniDeps bridges the gap between polyglot
versatility, architectural fidelity, and real-time execution performance.
